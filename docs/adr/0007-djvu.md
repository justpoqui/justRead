# ADR 0007 — DjVu: recognized, decoder pending a decision

**Status:** open, awaiting the maintainer's decision (Phase 4)

## Context
DjVu pages are encoded with four codecs: the ZP adaptive arithmetic coder, BZZ (Burrows-Wheeler)
for text/annotations, JB2 for bitonal masks, and IW44 wavelets for color layers. The reference
implementation, **DjVuLibre**, is GPL-2.0, which the project rules exclude without approval. No mature,
permissively licensed decoder (Rust or JavaScript) is known.

## Current behavior
`DjvuAdapter` recognizes DjVu files (magic `AT&TFORM` + `DJVU`/`DJVM`) and explains that they cannot be
opened yet, suggesting conversion to PDF.

## Options
1. **Write our own decoder** from the published DjVu v3 specification (Lizardtech, 2005): ZP + BZZ +
   JB2 + IW44 + page assembly, rendered into the existing fixed-layout engine as page images. Fully
   ours and Apache-2.0; a substantial, well-bounded project (estimate: one dedicated phase).
2. **Use DjVuLibre** (GPL) — not compatible with the project's license policy.
3. Leave DjVu unsupported.

Recommendation: option 1 as its own milestone after Phase 5, with test files generated by us.
